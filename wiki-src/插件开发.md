# 插件开发

ExtCircuitJS 的插件是可以热加载、可卸载、带权限声明的 ES module。本文从零写出一个能用的插件，并讲清全部扩展点。

> 契约定义在 `packages/plugin-api/src/index.ts`（`ExtPluginContext`）。
> 权限清单在 `packages/plugin-api/permissions.json`（**唯一权威表**，运行期与 lint 都读它）。

## 五分钟写一个插件

### 1. 建目录

```
plugins/my-plugin/
├── plugin.json     # 清单
└── index.js        # 入口
```

### 2. 写清单

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "0.1.0",
  "apiVersion": "1.0.0",
  "entry": "index.js",
  "mode": "in-page",
  "enabled": true,
  "permissions": ["ui.panel", "sim.observe"],
  "claims": { "panels": ["my-panel"] },
  "description": "在侧栏显示当前元件数，每步仿真刷新"
}
```

### 3. 写入口

```js
// plugins/my-plugin/index.js
export async function activate(ctx) {
    const el = document.createElement("div");
    el.textContent = "元件数：0";
    ctx.panel(el);                      // 挂进右侧栏

    let n = 0;
    ctx.on("analyze", () => {           // 每次分析后刷新
        n = window.ExtCircuitJS.api.listComponents().length;
        el.textContent = `元件数：${n}`;
    });
}

export async function deactivate() {
    // 面板与监听都由 fiber 自动撤销，通常无需手写
}
```

### 4. 注册进清单

编辑 `plugins/plugins.manifest.json`，在 `plugins` 数组里加一项（内容与 plugin.json 一致，宿主读的是这份）：

```json
{ "id": "my-plugin", "name": "我的插件", "version": "0.1.0", "apiVersion": "1.0.0",
  "entry": "index.js", "mode": "in-page", "enabled": true,
  "permissions": ["ui.panel", "sim.observe"], "claims": { "panels": ["my-panel"] } }
```

### 5. 跑起来

```bash
node tools/ext.mjs plugin lint     # 静态检查（禁令 + 权限一致性）
node tools/ext.mjs dev             # dev server 下刷新页面即可
```

刷新浏览器，右侧栏出现你的面板。

## 插件清单（plugin.json）

字段的权威定义在 `packages/plugin-api/manifest-fields.json`：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一标识，建议小写连字符 |
| `entry` | ✅ | 入口脚本（相对插件目录） |
| `version` | ✅ | 插件版本 |
| `mode` | | `in-page`（默认）或 `worker` |
| `enabled` | | `false` 则默认不自动加载 |
| `rev` | | 缓存版本键（热重载时换 URL） |
| `permissions` | | 能力声明数组，见[权限系统](#权限系统) |
| `claims` | | 你实际用到的东西（命令 id / 面板 / 钩子 / 元件），用于冲突检测 |
| `name` / `apiVersion` / `workerType` / `description` | | 元信息（`workerType` 仅 worker 模式用） |

> **写了不被识别的字段会被 lint 报错**，这是故意的：历史上 `inject: ["api"]` 看起来像依赖声明、实际没有任何代码读它，
> 害人误判。规则是"字段要么被运行时读取，要么被 lint 校验"。

## ctx 能力全景

`activate(ctx)` 拿到的 `ctx` 是所有能力的入口：

```ts
interface ExtPluginContext {
  readonly id: string
  readonly version: string
  readonly signal: AbortSignal        // dispose 时自动 abort
  readonly state: PluginState
  readonly permissions: readonly ExtPermission[]
  permits(perm): boolean              // 能力探测（缺权限时优雅降级）
  effect(fn): ExtDisposer             // 注册清理函数（LIFO 执行）
  on(event, handler): ExtDisposer     // 订阅事件         [sim.observe]
  hook(name, handler): ExtDisposer    // 包住 load/save    [document.hook]
  command(cmd): ExtDisposer           // 命令面板          [ui.command]
  panel(el, slot?): ExtDisposer       // 侧栏面板          [ui.panel]
  element: ExtElementFacet            // 自定义元件        [element.register]
  api: any                            // 读写电路/仿真     [sim.control]
  storage: { get, set }               // 按插件 id 隔离的持久存储（无需权限）
  log(...args): void                  // 带插件前缀的日志
}
```

### 事件

| 事件 | payload | 时机 |
|---|---|---|
| `analyze` / `update` / `timestep` / `svgren` | 上游回调参数 | 仿真钩子（多路复用，不再受上游单槽限制） |
| `select` | `{ count, elms, indices, ids }` | 选中集合变化 |
| `elemclick` | `{ elm, index, type, grid, screen, button }` | 点在某个元件上 |
| `elemdrag` | `{ phase, elms, indices, ids, grid, delta }` | 拖动中（每帧最多一条，`phase: start/move/end`） |
| `elementschange` | `{ added, removed, count, source }` | 元件增删（**看 source**：撤销/载入也走这条路） |

### 命令面板

```js
ctx.command({
  id: "my-plugin.reset",              // 全局唯一，建议 `${pluginId}.${name}`
  label: "复位到初始电路",
  category: "Ext",
  keywords: "reset 复位",
  run() { window.ExtCircuitJS.api.reset(); },
});
```

冲突规则：同 id 被第二个插件抢会**直接抛错**（不静默覆盖）；撞核心命令 id 也拒绝。

### 存储

```js
ctx.storage.set("lastValue", 42);
const v = ctx.storage.get("lastValue");   // → 42（按插件 id 隔离，底层 localStorage）
```

## 权限系统

权限**不是沙箱**（同源 ESM 仍能摸到 `window`），它做的是：把能力显式化、漏声明时激活即报错、让站点能按策略禁用某一面。

| 权限 | 通过什么暴露 | 说明 |
|---|---|---|
| `sim.observe` | `ctx.on(...)` | 订阅仿真/元件事件 |
| `sim.control` | `ctx.api` | 读网表/元件/测量，改参数、载入电路、推进仿真 |
| `ui.command` | `ctx.command(...)` | 注册命令面板项 |
| `ui.panel` | `ctx.panel(el)` | 挂 DOM 到右侧栏 |
| `ui.menu` | `ctx.element.register({ menu: true })` | 自定义元件出现在 Draw / 右键菜单 |
| `element.register` | `ctx.element.*` | 注册元件类与存档类型 |
| `document.hook` | `ctx.hook(...)` | 看见并改写存档文本 |

**三条规则**：

1. 声明了才能用 —— 未声明就调用会抛 `ExtPermissionError`（并且 `denial` 会区分「漏声明」/「被站点策略拦」/「名字拼错」）。
2. `claims` 要与实现一致 —— 不一致时记 warning；站点开启 `strictClaims` 则直接失败。作用是让冲突检测（比如两个插件抢同一个命令 id）保持准确。
3. 站点可以整体否决 —— `plugins.manifest.json` 的 `policy.denyPermissions`，或 `site.config.json` 的 `plugins.disabled`。

**优雅降级**：

```js
if (ctx.permits("sim.control")) { /* 用 ctx.api */ }
else { ctx.log("没有 sim.control，只读模式"); }
```

## 生命周期与清理

宿主用 **fiber**（对齐 cordis 语义）管理每个插件实例，保证"能加也能减"：

| 不变式 | 含义 |
|---|---|
| LIFO 释放 | `effect()` 注册的清理函数按**后进先出**执行 |
| 幂等 | 重复 `dispose()` 只执行一次，不抛错 |
| 迟到注册立即执行 | dispose 之后再 `effect(fn)` → `fn` 立刻执行（不会泄漏） |
| signal.aborted | dispose 后 `ctx.signal.aborted === true`，可用于取消异步任务 |

宿主自动撤销的东西：`ctx.panel` 的 DOM、`ctx.on` 的监听、`ctx.command` 的命令、`ctx.hook` 的钩子、`ctx.element.register` 的元件。

**激活失败会无条件回滚**（LIFO），不会残留已注册的资源。

**热重载**：

```js
await window.ExtCircuitJS.plugins.reload("my-plugin");        // 换 rev 重载
await window.ExtCircuitJS.plugins.reload("my-plugin", "v2");  // 指定版本键
```

reload 会真实重新 fetch manifest → deactivate 旧 fiber（全量释放）→ 以 `?rev=` 新 URL 重新 import。

**异步任务要配合 signal**：

```js
ctx.effect(() => { /* 清理 */ });
fetch(url, { signal: ctx.signal })     // dispose 时自动取消
```

## 自定义元件

插件不能 import core 模块，基类只能经 `ctx.element.base()` 取。

```js
export async function activate(ctx) {
  const Base = ctx.element.base("ResistorElm");   // 拿核心元件的构造函数
  const dumpType = ctx.element.freeDumpType();     // 找空闲的文本存档类型号

  class MyShunt extends Base {
    constructor(xa, ya, xb, yb, f, st) {
      super(xa, ya, xb, yb, f, st);
      if (xb === undefined) this.resistance = 0.5;  // 新放置时给默认值
    }
  }

  ctx.element.register({
    className: "MyShunt",          // ElementFactory 的键
    ctor: MyShunt,
    dumpType,                      // 文本存档类型号（写死，换号老存档读不回）
    xmlType: "MyShunt",            // XML 存档标签
    label: "Add My Shunt (0.5Ω)",  // 菜单文案
  });
}
```

**"完整可用"的四个条件**（缺一件就是半成品）：类进工厂、dumpType/xmlType 进映射、菜单有条目、卸载时四样一起撤回。
`ctx.element.register` 的 disposer 会把四样一起撤销。

参考实现：`plugins/ext-element/index.js`。

## 文档钩子（load/save）

包住 `loader.readCircuit()` 与 `app.dumpCircuit()`，让你看见并改写存档文本（格式扩展、旧档迁移、注释持久化）。

```js
ctx.hook("load", (text, meta) => {
  // 只在用户真的打开文件时改写（undo/recovery/paste 也走这里）
  return text.replace(/\r\n?/g, "\n");   // 返回字符串 = 替换；返回其它 = 不改
});

ctx.hook("save", (text, meta) => {
  if (meta.source !== "document") return; // save 侧务必按 source 过滤
  return text + "\n<!-- my-marker -->";
});
```

**两条纪律**：

1. **改写必须幂等** —— 同一段文本过两遍结果相同，否则「保存→打开→保存」会越改越多。
2. **save 侧按 `meta.source` 过滤，load 侧不过滤** —— 撤销快照/崩溃恢复也走这两个通道；
   save 不过滤会污染撤销快照，load 过滤会让崩溃恢复读不出来。**自己写出去的格式，自己必须无条件认得**。

参考实现：`plugins/ext-hook/index.js`。

## Worker 模式（隔离插件）

不可信插件可以跑在 Web Worker 里：拿不到 DOM、拿不到引擎对象，只能经 postMessage 向宿主取数据。

```json
{ "id": "my-worker", "entry": "worker.js", "mode": "worker", "workerType": "classic",
  "permissions": ["sim.observe"] }
```

```js
// plugins/my-worker/worker.js —— 运行在 Worker 线程
let seq = 0;
const pending = new Map();
const call = (method, params) => new Promise((res) => {
  const id = `w${++seq}`;
  pending.set(id, res);
  self.postMessage({ id, method, params });
});

self.onmessage = (ev) => {
  const msg = ev.data;
  if (msg.id?.startsWith("rpc-")) {          // 宿主的管理信号
    self.postMessage({ id: msg.id, ok: true, data: { ready: true } });
    return;
  }
  pending.get(msg.id)?.(msg);               // 宿主返回的数据
};

// 用法
const nl = await call("getNetlist");
```

宿主侧支持的方法：`getNetlist` / `getMeasurements` / `step` / `report`（按授予权限裁剪）。
**引擎对象永远不跨线程传递**，只传 JSON 数据。

参考实现：`plugins/ext-worker/worker.js`。

## 调试与排错

### 静态检查

```bash
node tools/ext.mjs plugin lint              # 全部插件
node tools/ext.mjs plugin lint plugins/foo  # 只查一个
```

lint 会检查：三禁令（禁 `import "../core"`、禁动态代码执行、禁裸 `document.write`）、
manifest 字段是否被识别、`permissions` 是否与源码实际调用一致、`claims` 冲突。

### 运行时状态

```js
window.ExtCircuitJS.plugins.list()
// [{ id, state, version, error, disposables, permissions, denied, warnings }]
```

- `state`：`discovered / loading / ready / failed / disposing / disposed`
- `warnings` 里能看到「claims 与实现不一致」「permission 被站点策略禁用」等非致命问题
- 激活失败会留在列表里（`state: failed` + `error`），不会"凭空消失"

### 常见问题

| 现象 | 原因 |
|---|---|
| `ExtPermissionError: 调用了 ctx.panel，但 manifest 未声明权限 "ui.panel"` | 在 `plugin.json` 与 `plugins.manifest.json` **两处**都加该权限 |
| `unknown manifest field "xxx"` | 写了不被契约识别的字段，删掉或改到正确字段 |
| 面板不出现 | 检查 `ui.panel` 权限；`ctx.panel(el)` 是否在 activate 里调用 |
| 热重载后旧逻辑还在跑 | 监听没走 `ctx.on`/`ctx.effect`（手工 `addEventListener` 不会自动清理） |
| 元件能放但存档读不回 | `dumpType`/`xmlType` 没注册，或换过 `dumpType` 号 |
