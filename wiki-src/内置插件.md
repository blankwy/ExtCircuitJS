# 内置插件

ExtCircuitJS 自带 10 个插件。**默认启用 4 个**（`hello` / `ext-theme` / `ext-neumorph` / `ext-share`），
其余 6 个是示例，默认关闭以免界面杂乱——它们是**开发参考**，读源码是学插件开发最快的路径。

| 插件 | 默认 | 类型 | 一句话 |
|---|---|---|---|
| [hello](#hello) | 开 | 示例 | 最小可用插件，验证插件系统 |
| [ext-theme](#ext-theme界面深浅色) | 开 | **功能** | 选项菜单切换深色/浅色 |
| [ext-neumorph](#ext-neumorph新拟态主题) | 开 | **功能** | 新拟态（软阴影浮雕）UI |
| [ext-share](#ext-share电路分享) | 开 | **功能** | 分享电路：URL / 单 HTML |
| [ext-panel](#ext-panel侧栏面板) | 关 | 示例 | 侧栏面板插槽 |
| [ext-command](#ext-command命令面板) | 关 | 示例 | 命令面板插槽 |
| [ext-event](#ext-event事件订阅) | 关 | 示例 | 订阅仿真/元件事件 |
| [ext-hook](#ext-hook存档钩子) | 关 | 示例 | 改写打开/保存的存档文本 |
| [ext-element](#ext-element自定义元件) | 关 | 示例 | 注册自定义元件 |
| [ext-worker](#ext-worker-worker-隔离模式) | 关 | 示例 | 隔离线程里运行的插件 |

**怎么启用/禁用**：编辑 `cover/site.config.json` 的 `plugins.disabled` 数组（详见[使用指南 · 插件管理](使用指南#插件管理)）。

## hello

**最小可用插件**。做三件小事，正好覆盖三个基础扩展点：

- 在侧栏挂一个面板，显示当前电路元件数与 analyze 触发次数
- 注册一个命令（命令面板里可搜到）
- 订阅 `analyze` 事件，每步仿真刷新计数

**为什么默认开**：它是"插件系统活着"的活体指示器。如果你在侧栏看到 `ExtCircuitJS · hello | analyze #N | M components`，
说明 boot、事件桥、插件宿主、面板插槽整条链路都正常。

代码：`plugins/hello/index.js`

## ext-theme（界面深浅色）

**【选项】菜单 → UI 外观**，点击在深色/浅色之间切换。

| 模式 | UI 外壳 | 画布 |
|---|---|---|
| 深色 | 深色背景、浅色文字、深色菜单/对话框 | 黑底白线（上游默认） |
| 浅色 | 默认浅色外壳 | 白底黑线（复用上游的 White Background 开关） |

**实现要点**（想自己写主题插件可以照抄）：

- 主题靠 `html[data-ext-theme="dark"]` + 一段覆盖 CSS，不改任何布局
- 画布联动走上游自带的 `printableCheckItem.toggle()`，顺带复用了它的 localStorage 持久化
- 切换状态自己记在 `localStorage["ext.theme"]`，下次打开自动恢复
- 卸载时摘掉样式表、删掉菜单项、清掉 data 属性

代码：`plugins/ext-theme/index.js`

## ext-neumorph（新拟态主题）

把 UI 美化成**新拟态（Neumorphism）**风格：软阴影、圆角、同色浮雕。**默认开启**。

### 视觉规范

| 元素 | 处理 |
|---|---|
| 底色 | `#e0e5ec`（统一背景） |
| 凸起（按钮/菜单/卡片） | 线性渐变 + 双向外阴影（暗 `#b8bdc7` / 亮 `#ffffff`） |
| 凹槽（输入框/轨道/按下态） | 双向内阴影 |
| 文字 | 标签 12px / 字重 600 / 0.2px 字距；正文 13px |
| 间距 | 统一 `--nm-gap: 10px` 节奏 |
| 滑块 | 深灰细轨 + 白色胶囊手柄（**canvas 重绘**，不是 CSS） |
| 画布 | 自动切白底（与新拟态浅色系匹配） |

### 为什么滑块要特殊处理

上游的拖动条（仿真速度 / 元件属性）是 **canvas 画出来的**（`Scrollbar` 类里 `getContext("2d")` 逐笔绘制），
CSS 完全管不到。插件用**运行时替换 `Scrollbar.prototype.draw`** 的方式接管绘制：

- 不改 `core/` 的任何文件（铁律），只在内存里换原型方法
- 钩子同时覆盖 UI 三个 bar 与元件属性滑块（`Adjustable` 内部也用同一个 `Scrollbar` 类）
- 补丁生效时统一重绘一次（否则静态截图还是旧画面），并挂 `update` 事件节流补绘（载入新电路后滑块会重建）

### 开关

【选项】菜单 → **新拟态样式**，默认开。状态记在 `localStorage["ext.neumorph"]`，卸载时恢复原样（含画布）。

### 自定义

所有颜色/圆角/阴影都提成了 CSS 变量，改插件顶部的 `:root` 块即可：

```css
--nm-bg: #e0e5ec;      /* 底色 */
--nm-dark: #b8bdc7;    /* 阴影暗色（调浅 = 更柔和） */
--nm-light: #ffffff;   /* 阴影亮色 */
--nm-gap: 10px;        /* 间距节奏 */
--nm-radius: 12px;     /* 圆角 */
```

代码：`plugins/ext-neumorph/index.js`

## ext-share（电路分享）

**默认开启**。命令面板（Shift 双击）搜「分享」，三条命令：

| 命令 | 作用 |
|---|---|
| 分享：生成链接并复制 | 生成 `?ctz=<LZ压缩电路>` 链接并复制到剪贴板——**对方点开即见电路、可仿真、可拖滑块** |
| 分享：仅复制链接 | 同上，不弹提示条 |
| 分享：下载单 HTML（含电路） | 下载一个 1–2 KB 的分享页，打开自动载入该电路并开始仿真 |

### 为什么这是最轻的交付路径

- 不需要对方安装任何东西（浏览器打开即可）
- 不需要传文件、不需要服务端：整个电路都在 URL 里
- lrc 这类电路约 400 字符 URL，小电路不到 100 字符

### 命令行等价

```bash
node tools/ext.mjs share --circuit lrc              # 内置语料
node tools/ext.mjs share --text "<电路文本>"        # 任意电路
node tools/ext.mjs share --circuit lrc --out x.html # 顺便出分享页
```

stdout 只有一行 URL，便于脚本抓取。详见 [分享电路](分享电路)。

### 实现要点（想自己写类似插件可以照抄）

- 压缩用 core 已挂的 `window.LZString.compressToEncodedURIComponent`（上游 exportasurl 同款）
- 链接基于 `location.href` 保留原站点路径（静态部署的子路径也正确）
- **单 HTML 不发起任何网络请求**：从当前 DOM 收集 `<script src>` / `<link href>` 再拼文档——既避免 SSRF 面，也省掉一次 fetch
- 生成后自动|手动复制到剪贴板（带 `execCommand` 降级，兼容非安全上下文）

## ext-panel（侧栏面板）

**示例**：演示 `ctx.panel(el)` 插槽——把任意 DOM 挂到右侧 `verticalPanel`。

- 面板节点带 `data-ext-plugin="ext-panel"` 标记，方便测试断言
- 卸载时节点被自动移除（fiber 的 disposer）

**学什么**：面板挂载/清理的标准写法；插件面板应带标记属性以便定位。

代码：`plugins/ext-panel/index.js`

## ext-command（命令面板）

**示例**：演示 `ctx.command({...})` —— 往命令面板注册一条命令。

- 命令 id 形如 `ext.command.ping`，执行次数写进 `ctx.storage`
- 第二个插件抢同一个 id 会被宿主**拒绝并抛错**（不静默覆盖）

**学什么**：命令注册/撤销、id 命名规范、冲突语义。

代码：`plugins/ext-command/index.js`

## ext-event（事件订阅）

**示例**：演示 `ctx.on(...)` 的多路复用事件总线，三种不同粒度各订阅一个：

| 事件 | 处理策略 | 为什么 |
|---|---|---|
| `analyze` | 只累加计数 | 每步仿真都来，不能做重活 |
| `elementschange` | 记一条摘要（**看 source**） | 撤销/载入/粘贴也走这条路，要区分 |
| `elemdrag` | 只在 `phase === "end"` 落盘 | 一帧最多一条，拖动中不做重活 |

**学什么**：事件粒度纪律；`elementschange.source` 的过滤习惯；拖动事件的合并帧语义。

代码：`plugins/ext-event/index.js`

## ext-hook（存档钩子）

**示例**：演示 `ctx.hook("load" | "save", ...)` —— 包住电路存档的读写，可以改写文本。

它做两件很实际的事：

- **load**：规范化外部存档（去 UTF-8 BOM、CRLF → LF、去掉本插件写的尾部标记）
  → 「带 BOM 的文件」「Windows 另存的文件」都能正常打开
- **save**：只在**用户真的在存文件**时（`meta.source === "document"`）追加一行版本标记

**学什么**（两条必须一起抄）：

1. 改写必须**幂等**（先删标记再追加，所以「保存→打开→保存」不会累积）
2. **save 侧过滤 `meta.source`，load 侧不过滤**——撤销快照也走 dumpCircuit，不过滤会污染；崩溃恢复也走 readCircuit，过滤了就读不回来

代码：`plugins/ext-hook/index.js`

## ext-element（自定义元件）

**示例**：演示 `ctx.element.register(...)` —— 插件注册一个**完整可用**的自定义元件（0.5Ω 分流电阻，电气行为复用核心 `ResistorElm`）。

"完整可用"= 四件事同时成立：

1. 类进 `ElementFactory`（能放置、能被 create）
2. `dumpType` / `xmlType` 进映射（存档能读回来）
3. Draw 菜单 / 右键菜单有条目（用户找得到）
4. 卸载时四样一起撤回

**学什么**：`ctx.element.base()` 取基类（插件不能 import core）、`freeDumpType()` 取空闲存档号、
"放置时给默认值 / 读档时保留文件值"的构造函数写法。

代码：`plugins/ext-element/index.js`

## ext-worker（Worker 隔离模式）

**示例**：演示 `mode: "worker"` —— 插件跑在 **Web Worker** 里，拿不到 DOM、拿不到引擎对象。

| 对比 | in-page 插件 | worker 插件 |
|---|---|---|
| 运行位置 | 主线程，共享 window | 独立线程 |
| 能摸 DOM/引擎 | 能（靠权限约束） | **不能** |
| 取数据方式 | 直接调 `ctx.api` | `postMessage` RPC 向宿主要 |
| 适合 | 可信插件、要改 UI | 不可信插件、纯计算 |

宿主侧提供服务方法：`getNetlist` / `getMeasurements` / `step` / `report`（按授予权限裁剪）。
**引擎对象永远不跨线程传递**，只传 JSON 数据。

**学什么**：Worker 插件的 postMessage 协议、宿主如何按权限 serve、隔离的边界在哪。

代码：`plugins/ext-worker/worker.js`（默认 `enabled: false`）
